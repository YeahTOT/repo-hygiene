## 1. 建议的目录结构（供参考，非强制）

```text
project/
  AGENTS.md
  pyproject.toml
  src/<package>/{data,models,training,evaluation,inference,utils}/
  configs/
  scripts/
  tests/
  experiments/
  docs/
  outputs/               # 通常不纳入版本控制
```

采用项目自身已有的合理命名和层次，不因示例结构而强制重排全部目录。优先通过 `configs/` 或 `experiments/` 管理配置变体，不要不断生成 `train_final_v2.py` 等脚本。不同基线、消融实验及可复现的独立模型应明确记录并保留。

建议：

- 训练/评估逻辑尽量共用，通过明确配置区分模型和实验，而不是复制整套训练脚本。
- 保持稳定且简洁的公开接口；使用薄 CLI 包装层记录可复现的实验命令。
- 在仓库中保留实验配置和必要的运行元数据；大型数据集、权重及日志使用外部产物存储，或按照明确的版本管理策略处理。
- 危险重构前，优先补充预处理不变量、张量形状、评价指标、模型加载和导出相关测试。

## 2. `repo_audit.py` 扫描结果说明

有 Git 时，脚本优先扫描**已跟踪文件和未忽略的新增文件**，不遍历已忽略的大型数据集和权重。没有 Git 时，扫描普通文件并跳过常见生成目录、第三方目录和数据目录。

| 问题标识（JSON 保留英文） | 含义 | 建议处理 |
| --- | --- | --- |
| `generated_artifact` | 权重、模型导出、缓存、日志或产物目录中的文件 | 已跟踪的生成目录文件为高优先级，其余先核实是否为测试样例 |
| `duplicate_content` | Python/配置文件的 SHA-256 完全相同 | 列为合并候选，禁止自动删除 |
| `versioned_name` | 文件名包含 `_final`、`_copy`、`_bak`、`_new`、`_vN` 等 | 命名提醒，也可能是合理的模型版本 |
| `unexpected_top_level` | 顶层目录不属于显式提供的 `--allowed-top` 列表 | 确认目录约定之前只作提示 |
| `oversized_python` | Python 文件超出建议的行数限制 | 可考虑拆分，不代表代码错误 |

此脚本**不具备**函数/类存活性判定、跨文件语义重复检测、循环依赖分析和功能等价性证明。需要结合代码导航及相关工具进一步确认，不能把低置信度结果作为删除依据。

## 3. 证据和风险分级

- **P0：** 已确认训练、推理、导出流程损坏，或出现可能泄露信息、必须紧急处理的大型敏感产物。
- **P1：** 正在使用的重复实现出现行为分叉、包边界明显破坏，或确认废弃的代码造成较大维护负担。
- **P2：** 疑似过时代码、不必要的包装层、版本后缀脚本、依赖声明漂移。
- **P3：** 命名、目录排布等非功能性问题。

删除任何文件前，至少确认：没有 Python/CLI/注册器/配置引用，没有记录中的实验或部署使用者；具备相关测试或轻量验证；更改可恢复。**无法证明代码被调用，不等于证明它已经废弃。**

对于深度学习项目，还需评估 `state_dict` 键名、checkpoint 兼容性、输入格式、前向传播形状和 dtype、损失函数语义、数据增强、随机性、ONNX/OM 接口名和部署性能限制。

## 4. 接入质量门禁

完成项目本身的环境配置后，可按需执行：

```bash
python3 /path/to/repo-hygiene/scripts/repo_audit.py --root . --json
ruff check .
ruff format --check .
pytest -q
```

用 `--changed-from HEAD` 检查未提交的修改，或提供分支共同祖先的引用来检查整个分支的改动。`--fail-on high` 仅在存在高优先级检查结果时返回失败状态。对老仓库先建立基线或仅检查新增问题，避免历史遗留告警阻塞无关改动。

在与用户确认实际目录规范后，才能配置 `--allowed-top`。规则建议记录在项目自己的 `AGENTS.md` 和 CI 配置中；**仅靠 Skill 提示词无法实现强制拦截**。
